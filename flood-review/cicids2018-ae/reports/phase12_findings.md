# Phase 12 findings: label-free threshold selection (exploratory)

Script `src/phase12_thresholds.py`, tables in `reports/phase12_thresholds.md`, numbers in `results/phase12_thresholds.json`. It uses only saved scores (no retraining). The methods were written down before the first run, but `F-ben-p95` is a grid member I included knowing that the 99th-percentile rule had performed poorly in Phase 3, so that comparison is not blind. Each model was trained once; the intervals describe resampling of the evaluation set only. All values below are F1 at the natural prevalence unless stated.

## What the numbers show

1. **For the one-class autoencoder (seen attacks) the fixed 99th-percentile rule is the problem, not the score.** F1 is 0.013 with the 99th percentile of clean benign validation scores and 0.600 with the 95th percentile (recall 0.675, false-positive rate 0.078), against 0.652 for the best possible threshold on the test set (which uses test labels) and 0.650 for the validation-F1-tuned threshold (which uses validation labels). The 95th-percentile rule needs a clean benign reference sample but no labels on the target data.
2. **Knowing the true attack prevalence does not fix it.** Flagging the top true-prevalence share of the target gives F1 0.005 at prevalence 1% and 0.009 at 5% (0.514 at the natural 11.9%). The highest-scoring records at low prevalence are mostly benign outliers, so the top of the ranking is not where the attacks are. This agrees with the earlier finding that recall at 1% false positives is only 0.005.
3. **A Gaussian-mixture estimate of the attack share (P-gmm) gave near-best F1 for the one-class model but is a poor estimate of prevalence.** F1 0.605 at natural prevalence and 0.858 at prevalence 50% (best possible 0.886; fixed 95th percentile 0.770). Its estimated share was 0.084 when the true share was 0.010, and 0.235 when it was 0.119. In the unseen-attack setting it was worse than the fixed rule for the unsupervised model (0.332 against 0.507 at natural prevalence).
4. **The simple tail-ratio estimator (P-tail) failed.** For the one-class model it estimated zero attacks at every prevalence, so it flagged nothing (F1 0.000). The likely cause is that the benign tail of the test blocks is heavier than that of the validation blocks, which breaks the assumption that benign traffic looks the same in the reference and the target. This is a diagnosis from the pattern of results, not a separate test.
5. **The strictly unsupervised model has no useful threshold at all in the seen setting.** Its best-possible F1 (0.219) is barely above flagging every record (0.213), and the validation-F1-tuned threshold equals flag-everything.
6. **Alert budgets** (flag the top q%) only work when q is at or above the true prevalence: for the one-class model B-10% gives 0.442 at natural prevalence but falls to 0.242 at 50% prevalence.

## What this does and does not support

The result supports the point that threshold choice, not ranking quality, explains much of the weak recall of the reconstruction detectors here, and that a lower percentile on a clean benign reference recovers most of the achievable F1 for one model. It does not show that estimating attack prevalence is a good way to set the threshold: the two estimators tried were either badly off (P-gmm) or failed (P-tail), and exact prevalence knowledge did not help at low prevalence. Better estimators (for example mixture-proportion estimators designed for this purpose) were not tested. Nothing here has been checked against the literature, so no novelty is claimed.

Limits: one trained model per setting; one dataset; the clean reference sample is selected using benign labels once (as the one-class threshold rule already did); resampled targets reuse the same test records, so the five resamplings are not independent data.
