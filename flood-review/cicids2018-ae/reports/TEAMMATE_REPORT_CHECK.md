# Check of the teammate's report against the verified project results

File checked: "CICIDS2018 Autoencoder IDS - Final Project Report.pdf" (27 pages). The statements below do not match what the project's own result files and reports show. Page numbers refer to the PDF. The capstone thesis (`reports/CAPSTONE_THESIS.docx`) was written from the verified report and result files, and does not repeat these statements.

| Page | Statement in the teammate's report | What the project shows |
|---|---|---|
| 3 (Section 1.4, Table 2) | The unsupervised autoencoder (Phase 3) is trained on "benign network flows only (label = 0)". | The unsupervised autoencoder is trained on 1 million unlabelled rows that contain about 12% attacks. The benign-only model is the separate one-class autoencoder. The effect of this contamination (ROC-AUC 0.468 against 0.889 with clean training data) is a central result. |
| 3 (Table 2) | The supervised autoencoder has a "joint reconstruction and supervised discrimination objective". | Only the supervised autoencoder with decoder adds a reconstruction term. The plain supervised autoencoder uses class-weighted cross-entropy only (attacks weighted 7.14). |
| 8, 20, 26 (Table 6, Section 6.6, Table 25) | DAE-LR is a "Denoising Autoencoder and Low-Rank" model with "input denoising noise + low-rank latent constraints". | DAE-LR (Nkashama et al., arXiv:2407.08838) is a latent-regulated autoencoder: reconstruction loss plus lambda times the squared distance of the latent code to a learnable centre. The 8 models per seed are 4 values of lambda, each trained on unlabelled mixed data and as a benign-only control. |
| 8 (Table 6) | Phase 8, confidence-aware adaptation, "prevents self-training poisoning". | It did not. The confidence gate gave no clear advantage over unrestricted updates (F1 difference +0.059, interval -0.013 to +0.131) and did not reduce the attack share of the retraining buffer (0.128 against 0.123). |
| 8, 19-20 (Table 6, Section 6.4) | Phase 9 is "controlled concept drift stress testing" with "explicit concept-drift regimes". | No drift was injected. The stream is the real chronological order of the dataset; its change points are jumps between days, two of them on one-hour snapshot days. |
| 8, 22, 27 (Table 6, Section 8.6) | Phase 17 gives "fast online recovery from concept drift" and demonstrates supervised-gated drift recovery. | The ranking recovered (ROC-AUC 0.079 to 0.741 on 16 February) only with a gate that already knew the attack types, and that gate (Phase 4 model) was trained on all days and is optimistic. With a gate that never saw Hulk, HOIC and Bot there was no recovery on 16 February and the ranking was lost on 2 March. The overall F1 did not change (0.0247 to 0.0251). |
| 8 (Section 2.5), 27 | The repository "resolves all four literature gaps" and offers "bit-for-bit reproducible baselines". | Bit-for-bit reproduction was shown for Phases 3 to 6 on the original machine on 2026-11-11. On other machines the results are close but not identical (the report says so on page 26). "Resolves all four gaps" is not supported. |
| 27 (Table 26) | "Automated verification guarantees 100% consistency between JSON and report." | The 138 checks cover the Run A numbers of Tables 1 to 5 of the report. Later tables have their own checks (48 for trimmed loss, 176 for DAE-LR, 12 for labelled thresholds) or recounts. A guarantee of 100% consistency is not claimed anywhere in the project. |
| 24 (Table 24) | "All verifiers and unit tests passing." | The test suite is 51 passed and 1 skipped (the skipped test needs PyTorch, which cannot be loaded on the laptop). One PCAP test can time out when the machine is busy; it passes when run alone. |
| 9, 25, 27 (Sections 1.5, 3.3, 8.1, Table 26) | Loading the 10 CSV files in memory "triggers immediate out-of-memory termination" and "caused OOM crashes". | No such crash is recorded in the project files. What is documented is that the preprocessing reads each file in chunks of 500,000 rows and writes float32 arrays to disk. Treat the out-of-memory statements as unverified. |
| 22-23 (Section 7.2) | Four additional seeds 1 to 4 on Google Colab. | The report's Tables 1c and 5c use seeds 1, 2, 3 and 42 on the laptop, and Run B on Colab is a repeat of seed 42. The README command uses seeds 1 to 4 on Colab. The team should confirm which seeds were run where before stating it. |
| 6-7 (Section 2.3) | A "critical review of published autoencoder intrusion detection studies" finds four recurring flaws. | No sources are cited for this review. It reads as a general statement, not a finding of this project. |
| 5-6, 9-10 | Data sizes "6.41 GB", "13 GB" processed. | Correct if read as GiB: the raw files are 6.41 GiB (6.89 GB) and the intermediate and processed arrays 13.1 GiB on the laptop. The 15.6 GB memory figure is also correct (Windows reports 15.63 GB). |

Also note: the teammate's report contains no result tables (no ROC-AUC, F1 or recall values for the main comparison), no novelty assessment and no limitations of the findings. The thesis adds these from the verified report.
